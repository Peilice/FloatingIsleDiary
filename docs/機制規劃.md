# 浮島日記（Floating Isle Diary）機制規劃（單一依據）

> 這份是機制的唯一依據。`遊戲企劃.md` 只保留世界觀、美術、技術、風險；`課程對照表.md` 只保留課綱條目與單字範圍。
> 三份文件衝突時，以本文件為準。
> 美術與語音不在本文件範圍，最後處理。

---

## 0. 驗收原則（每個機制都要通過）

**忽略測試**：如果孩子不看英文、不管科學，只是亂點亂拖，成功率是否和認真玩一樣高？
- 一樣高：這個機制沒有在教東西，必須重做。
- 英文類機制，亂猜的成功率應接近隨機（選項數的倒數）。
- 科學類機制，不理解概念的玩法應該明顯比較慢或比較差，但**不會卡死**。

**每個機制必須有**：玩家決策、依賴的概念或英文句子、失敗長什麼樣、怎麼復原、`ok` 怎麼判定、解鎖條件、課綱代碼。

**共同底線**
1. 沒有懲罰：不扣資源、不死亡、不離開。失敗只讓事情變慢，或換個方式再試。
2. 沒有死局：任何狀態都能復原（見 §3.2 鏟子、§4 各模組的「復原」欄）。
3. 不把答案自動做完：玩家必須選擇，不能「有東西就自動交出去」。
4. 聲音不是唯一線索：所有聽力線索都有視覺對應，靜音也能玩（無障礙，也避免平板音量問題）。

## 1. 單字追蹤與 `ok` 定義

### 1.1 事件定義

| 欄位 | 定義 | 用途 |
|---|---|---|
| `seen` | 單字被看到或聽到一次 | 只用於統計，**不用於淡出** |
| `ok` | 玩家在**有 3 個以上選項**時，**第一次選擇就正確**，且沒有使用過提示（peek） | 淡出階段、家長端報告 |
| `miss` | 選錯，或使用提示後才答對 | 排程優先度、階段回退 |
| `days` | 出現過 `ok` 的不同天數 | 淡出條件 |
| `last` | 最近一次出現的遊戲日 | 排程 |

> M1 原型的缺陷（已列在 §2）：每天預報就替天氣字加 `ok`、只要背包有東西就自動交給居民，兩者都是「曝光」而不是「答對」。

### 1.2 提示階段（玩家看不到階段名稱）

| 階段 | 進入條件 | 顯示 |
|---|---|---|
| 0 | 新字 | 圖＋英文＋中文＋語音 |
| 1 | `ok ≥ 2` 且 `days ≥ 2` | 圖＋英文＋語音 |
| 2 | `ok ≥ 4` 且 `days ≥ 3` | 只有英文＋語音，點一下才露出圖（算 `miss`） |
| 回退 | 同一字連續 2 次 `miss` | 退回前一階段；階段用的進度點降回該階段入口，要再答對才回得去（給家長看的 `ok` 累計值不扣） |

### 1.3 願望與任務的排程器（取代 M1 的隨機挑選）

**目標**：新字在 3 天內至少回來 3 次，弱字比熟字更常出現，每天新字不超過 2 個。

```
每次要產生一個願望時：
1. 候選池 = 已解鎖區域與模組內、玩家「手上做得到」的詞（有對應物品或設施）
2. 分三類：
   新字（seen=0）      每天最多引入 2 個
   弱字（miss>=ok 或 ok<2） 
   熟字（ok>=4 且 days>=3）
3. 抽取權重：
   到期的複習字（新字引入後的第 0 天、第 1 天、第 2 天）  權重 5
   弱字                                                  權重 3
   一般字                                                權重 1
   熟字                                                  權重 0.3（仍會出現，避免遺忘）
4. 不連續出現同一字；同一次最多 1 個新字
6. （M2 模擬後新增）今天還有到期的複習字時不引入新字，讓新字的引入速度配合實際的出題量
5. 干擾項 = 同模組、同詞類、已學過的字，優先挑易混淆的（例如 carrot 與 corn）
```

**複習時程**：新字第一次出現（天 0）→ 同日稍晚一次（約 5 分鐘後）→ 天 1 → 天 2。三天內共 4 次曝光，至少 3 次是需要選擇的情境。

**M2 模擬結果**（`tools/sim/sim_sched.js`，40 字、每 5 天解鎖 4 字、100 天）：

| 每天願望數 | 1 | 2 | 3 | 4 | 6 | 8 |
|---|---|---|---|---|---|---|
| 新字 3 天內 ≥3 次 | 0% | 18% | 43% | 50% | 95% | 98% |

- 弱字每次被選中的機率是熟字的 5～9 倍；單日新字不超過 2 個；沒有連續同字。
- **目標要每天約 6 個願望才達得到**。每天 1 個願望時，「不連續同字」和「3 天內 3 次」本身就互相矛盾。
- 遊戲的一天是 60 秒，「同日稍晚約 5 分鐘」在遊戲中不存在；「3 天」實際上是 3 分鐘。**待決定**：時間窗改用「接下來 N 次出題」計算，或增加每天的願望來源（M3 的多位居民、市集）。
- 目前遊戲只有 3 個候選字，每天 2 個以上願望即可達成目標。

## 2. M1 原型審查（已用模擬驗證）

### 2.1 發現的問題

| # | 問題 | 嚴重度 | 處理 |
|---|---|---|---|
| 1 | 居民願望：背包有東西就自動交出，玩家沒有選擇，英文不影響成功 | 高 | **改為選取物品再交給居民**，選錯會搖頭，不扣東西（M2 已完成） |
| 2 | `ok` 在每天預報時就加，天氣字會在沒學會時淡出 | 高 | 套用 §1.1 定義；預報改為「選天氣圖示」互動（§4.3）（M2 已完成） |
| 3 | 玫瑰種在樹蔭永遠長不大（光 0.7 > 樹蔭最多 0.5），也沒有挖掉的方法 | 高 | 已改為連續速率生長（已套用）；新增鏟子（M2 已完成） |
| 4 | 數值太快：所有植物第一天就成熟，天氣幾乎沒有影響 | 高 | 已調整（見 2.2，已套用） |
| 5 | 雨天所有植物都停止生長 | 中 | 已解決（連續速率下雨天仍有 15% 光） |
| 6 | 重置存檔會被舊頁面的 `pagehide` 存檔蓋回去 | 中 | 已修：用 `?reset=1`，在新頁面載入時清除 |
| 7 | 教學固定叫玩家種紅蘿蔔，改種別的提示會錯 | 低 | 教學步驟改為檢查「是否已完成」而不是檢查種類（M2 已完成） |

### 2.2 模擬結果與採用的數值

用 `sim_m1.js`、`sim_m1b.js`、`sim_m1c.js` 以 Monte Carlo（每組 3,000 次）模擬。

**原模型的問題**：離散門檻（光照達標才長）搭配 20～30 秒的成熟時間，一天 60 秒，所以植物第一天就成熟，且玫瑰在樹蔭 100% 卡死。

**新模型**（已套用到 `game.js`）：生長速率 = `min(1, 光照 ÷ 光需求)`，水量低於 0.2 時停止；乾燥速率減半，澆水一次可撐約一天。

| 植物 | 成熟秒數 | 向陽勤澆 | 向陽只澆一次 | 樹蔭勤澆 | 樹蔭只澆一次 |
|---|---|---|---|---|---|
| 紅蘿蔔 | 75 | 2.0 天 | 2.6 天 | 2.5 天 | 4.2 天 |
| 豆子 | 110 | 2.9 天 | 4.9 天 | 3.7 天 | 6.2 天 |
| 玫瑰 | 150 | 4.1 天 | 7.5 天 | 6.5 天 | 12.1 天 |

（一天 60 秒。90% 分位數最慢：玫瑰樹蔭只澆一次 17 天，約 17 分鐘，屬於「偷懶的代價」可接受。卡死比例全部為 0%。）

**驗證結果**：天氣現在有意義（陰雨天延遲 1～3 天）、勤澆比不澆快約 1.5～2 倍、沒有任何組合卡死。

## 3. 核心系統

### 3.1 時間與天氣

| 項目 | 規則 |
|---|---|
| 一天 | 60 秒，之後換天氣 |
| 天氣 | 晴 0.4、多雲 0.25、雨 0.25、風 0.1，**不連續相同** |
| 預報 | 每天開始時播報；延伸層可看「明天預報」（氣象站，INd-Ⅱ-7） |
| 光照 | 晴 1.0、風 0.8、多雲 0.4、雨 0.15；樹蔭 ×0.5 |
| 水分 | 晴 -0.010/秒、多雲 -0.006、風 -0.015、雨 +0.08；澆水 +0.6 |
| 暫停 | 圖鑑、設定開啟時暫停時間 |
| 設定 | 上方齒輪按鈕：**中文字幕**開關（英文句子下方的中文翻譯：Pip 引導、居民願望、天氣播報、天氣題、日記選項；圖鑑的中文說明是科學內容，不受影響）、聲音開關；存在存檔，預設開 |

### 3.2 種植（含復原）

| 動作 | 規則 |
|---|---|
| 種 | 選種子再點空地；每塊地一株 |
| 澆水 | +0.6，上限 1 |
| 收成 | 成熟時點擊，得到作物 +1 星砂 |
| **鏟子（新增）** | 挖掉任何植物，**返還種子**，地塊恢復空地；解決種錯位置、種錯植物 |
| 枯黃 | 水量 < 0.08 時變黃，澆水立刻恢復，不會死 |

### 3.3 居民與願望（修正自動交付）

| 項目 | 規則 |
|---|---|
| 提出 | 氣泡顯示英文句（依階段加圖、中文）；點氣泡可重聽。**M2 實作**：重聽本身不算 `peek`（聽英文正是要鼓勵的事），在階段 1、2 點氣泡會露出隱藏的圖或中文，這時才算 `peek`；手上沒拿東西時點居民也是重聽 |
| **交付** | 玩家從背包**選一個物品**，再點居民。背包至少放 3 種物品（含干擾項，來自 §1.3 干擾規則）才算有效選擇 |
| 正確 | 星砂 +5、愛心動畫、該字 `ok +1`（若未用 peek） |
| 錯誤 | 居民搖頭，物品退回，該字 `miss +1`，句子再唸一次並露出圖。**不扣任何東西** |
| 下一個願望 | 由 §1.3 排程器挑選，約 2.5 秒後出現。**M2 實作**：背包裡的物品不顯示英文名稱，選物品時會唸出它的英文；`ok` 只在背包有 3 種以上物品時才算（開局只有 1、2 種時，答對不加 `ok` 也不加 `miss`） |
| 物品不足 | 玩家背包沒有可選項時，居民改提出「做得到的」願望（只能是已種過的作物） |

### 3.4 星砂、擴建與圖鑑

| 項目 | 規則 |
|---|---|
| 星砂 | 收成 +1、交付願望 +5、圖鑑新發現 +3 |
| 擴建 | 星砂換地塊、設施、新區域；**所有設施都能拆除並返還 50%**（防止建錯卡死） |
| 圖鑑 | 以遊戲行動解鎖；點卡片聽發音並顯示一句事實。稀有項需特定條件組合 |

### 3.5 日記（名稱呼應的核心系統）

| 項目 | 規則 |
|---|---|
| 時機 | 每天結束時（60 秒的一天走完）自動進入「寫日記」，也是一次遊玩的自然結束點 |
| 內容 | 以簡單句型記錄當天發生的事，例如 `Today it was rainy. I planted a carrot.`，句子由當天的事件拼出，不是玩家自由輸入 |
| 決策 | 日記每句有一個空格，玩家從 3 個詞中**選一個填入**（天氣、作物、居民名稱），選項來自當天真正發生的事，答案是從當天的經歷中回想 |
| 失敗／復原 | 選錯會露出當天的小圖提示，可再選；日記一律會完成，不會漏寫 |
| ok | 第一次填對 |
| 價值 | 提供「以句子回顧」的機會（英語 Ae-Ⅲ-12、B-Ⅲ-1、Ad-Ⅲ-11），並讓核心層的單字在每天結尾再出現一次；日記本可以翻回前面的頁面，孩子能看到自己的島如何成長 |
| 忽略測試 | 3 選 1 亂猜 33%，但答案只能靠當天的記憶，不看英文也不看經歷就很難全對 |
| 核心層與延伸層 | 核心層：一句、一個空格；延伸層：三句、拼寫空格（4-Ⅲ-3） |
| M2 實作 | 句型：`Today it was ___.`、`I planted a ___.`、`I picked a ___.`、`I gave a ___ to the rabbit.`，事件句權重是天氣句的 2 倍。當天同類事件有兩種以上時，那些字不能當干擾項；湊不到 3 個選項的句型就不出（只有 3 種植物時，當天種了兩種就只會出天氣句）。答案字在階段 0 時選項附中文。寫完按 `Good night` 進入隔天；日記本（上方「日記」按鈕）可翻閱 |

### 3.6 家長端

長按設定 3 秒並解一題算術開啟。顯示：玩了多久、每個單字的 `ok / miss / days`、每個課綱條目是否接觸過、可重設進度。資料只存本機。

## 4. 各模組機制卡

### 欄位說明
**決策**＝玩家必須選擇什麼；**依賴**＝這個決策靠哪個概念或英文；**失敗／復原**；**ok**＝何時算答對；**忽略測試**＝亂點的結果。

### 4.1 植物（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | 哪種植物放哪一塊地（向陽或樹蔭）、何時澆水、要不要鏟掉重種 |
| 依賴 | 光與水的需求（INa-Ⅱ-7、INe-Ⅱ-11）；植物名稱英文（願望） |
| 失敗／復原 | 長得慢但不停；缺水停止、澆水恢復；鏟子重種 |
| ok | 願望交付時選對作物（§3.3） |
| 忽略測試 | 亂種亂澆：玫瑰種樹蔭要 6.5 天，種向陽要 4.1 天，缺水要 7.5 天，明顯較慢 |
| 課綱 | INb-Ⅱ-6、INa-Ⅱ-7、INe-Ⅱ-11、INd-Ⅱ-3 |

### 4.2 植物各部位（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | 居民要「根／花／種子」類的物品，玩家要選對植物來收成 |
| 依賴 | 「紅蘿蔔吃根、豆子吃種子、玫瑰看花」（INb-Ⅱ-6）；英文 root / flower / seed |
| 失敗／復原 | 收成錯植物不扣東西，可再種 |
| ok | `I want a root.` 之類的要求，選對作物 |
| 忽略測試 | 3 選 1，亂猜 33% |
| 課綱 | INb-Ⅱ-6、INb-Ⅱ-7 |

### 4.3 天氣（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | **每天早上居民問 `How is the weather?`，玩家從 4 個圖示中選出今天的天氣**；以及依天氣決定今天做什麼（雨天不澆水、晴天種玫瑰）。**M2 實作**：第 1 天不問（先讓教學進行）；卡片顯示方式依正確答案字的階段：0＝圖＋英文＋中文、1＝圖＋英文、2＝只有英文，可按放大鏡露出圖（算 `peek`）；回答前上方不顯示天氣圖示；重聽題目不算提示 |
| 依賴 | 天氣英文單字與圖示對應；雨天水分自動補充的因果（INd-Ⅱ-6、INd-Ⅱ-7） |
| 失敗／復原 | 選錯圖示會搖晃並再聽一次，不影響遊戲 |
| ok | 第一次就選對圖示 |
| 忽略測試 | 4 選 1，亂猜 25%；看天空其實也能答，所以這題訓練的是「英文單字和圖示的對應」，不是觀察 |
| 課綱 | INd-Ⅱ-6、INd-Ⅱ-7、INd-Ⅱ-4 |

### 4.20 食物鏈與生態平衡（延伸，生態研究所）
**重要設計變更**：用**承載量模型**，不做自由族群動態。

模擬結果（`sim_food.js`）：草、兔、狐的連續動態模型在 5 組參數下，300 天內**全部會崩潰**；就算加上保底，保底每 1～2 天就觸發一次（121～291 次/300 天），代表系統是靠作弊撐住的。

| 項目 | 規則 |
|---|---|
| 平衡值 | 草的承載量 = 草地面積 × 10；兔的平衡 = 草 ÷ 10；狐的平衡 = 兔 ÷ 4 |
| 變化 | 每天向平衡值靠近 1 格，**單調收斂，不會振盪或滅絕** |
| 玩家決策 | 增加草地、放置狐穴或兔窩，改變平衡值；介面用箭頭顯示每個物種「變多、變少、穩定」 |
| 事件 | 兔子變太多時草被吃光，玩家看到草地變禿，補種草或建狐穴 |
| 失敗／復原 | 任何比例都能收斂，不會滅絕 |
| ok | 事件前選出正確處置 |
| 課綱 | INa-Ⅲ-10、INc-Ⅲ-9、INe-Ⅲ-12 |

**M2 忽略測試結果**（`?bot=1&fast=20`，Chrome，99 個遊戲日，機器人每 0.12 秒在能點的東西中隨機點一個）：

| 機制 | 第一次就對 | 理論隨機值 | 判定 |
|---|---|---|---|
| 天氣題（4 選 1） | 33%（33/99） | 25% | 接近隨機，通過 |
| 日記（3 選 1） | 36%（36/99） | 33% | 接近隨機，通過 |
| 交付（背包 3 種） | 50%（7/14） | 33% | 樣本太少（機器人每天只收成 0.54 次），待加長測試 |

**發現的問題（待決定）**：亂點 99 天後，7 個字中有 4 個升到階段 1。因為階段只看累計 `ok` 和天數、不看正確率，長期亂猜也會慢慢淡出提示。建議加一個條件，例如最近 5 題的正確率至少 60% 才能升階。
