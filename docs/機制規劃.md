# 浮島日記（Floating Isle Diary）機制規劃（單一依據）

> 這份是機制的唯一依據。`遊戲企劃.md` 只保留世界觀、美術、技術、風險；`課程對照表.md` 只保留課綱條目與單字範圍。
> 三份文件衝突時，以本文件為準。
> 美術與語音不在本文件範圍，最後處理。

---

## 0. 驗收原則（每個機制都要通過）

**忽略測試**：如果孩子不看英文、不管科學，只是亂點亂拖，成功率是否和認真玩一樣高？
- 一樣高：這個機制沒有在教東西，必須重做。
- 英文類機制，亂猜的成功率應接近隨機（選項數的倒數）。
- 科學類機制，不理解概念的玩法應該明顯比較慢或比較差，但**不會卡死**。

**每個機制必須有**：玩家決策、依賴的概念或英文句子、失敗長什麼樣、怎麼復原、`ok` 怎麼判定、解鎖條件、課綱代碼。

**共同底線**
1. 沒有懲罰：不扣資源、不死亡、不離開。失敗只讓事情變慢，或換個方式再試。
2. 沒有死局：任何狀態都能復原（見 §3.2 鏟子、§4 各模組的「復原」欄）。
3. 不把答案自動做完：玩家必須選擇，不能「有東西就自動交出去」。
4. 聲音不是唯一線索：所有聽力線索都有視覺對應，靜音也能玩（無障礙，也避免平板音量問題）。

## 1. 單字追蹤與 `ok` 定義

### 1.1 事件定義

| 欄位 | 定義 | 用途 |
|---|---|---|
| `seen` | 單字被看到或聽到一次 | 只用於統計，**不用於淡出** |
| `ok` | 玩家在**有 3 個以上選項**時，**第一次選擇就正確**，且沒有使用過提示（peek） | 淡出階段、家長端報告 |
| `miss` | 選錯，或使用提示後才答對 | 排程優先度、階段回退 |
| `days` | 出現過 `ok` 的不同天數 | 淡出條件 |
| `last` | 最近一次出現的遊戲日 | 排程 |

> M1 原型的缺陷（已列在 §2）：每天預報就替天氣字加 `ok`、只要背包有東西就自動交給居民，兩者都是「曝光」而不是「答對」。

### 1.2 提示階段（玩家看不到階段名稱）

| 階段 | 進入條件 | 顯示 |
|---|---|---|
| 0 | 新字 | 圖＋英文＋中文＋語音 |
| 1 | `ok ≥ 2` 且 `days ≥ 2` | 圖＋英文＋語音 |
| 2 | `ok ≥ 4` 且 `days ≥ 3` | 只有英文＋語音，點一下才露出圖（算 `miss`） |
| 升階的共同條件（M3 起） | 最近 5 題正確率 ≥ 60% | M2 忽略測試發現只看累計 `ok` 時，亂猜 99 天也會讓 7 個字中的 4 個升階；加上後亂點 118 天只有 1 個字升階 |
| 回退 | 同一字連續 2 次 `miss` | 退回前一階段；階段用的進度點降回該階段入口，要再答對才回得去（給家長看的 `ok` 累計值不扣） |

### 1.3 願望與任務的排程器（取代 M1 的隨機挑選）

**目標**：新字在 3 天內至少回來 3 次，弱字比熟字更常出現，每天新字不超過 2 個。

```
每次要產生一個願望時：
1. 候選池 = 已解鎖區域與模組內、玩家「手上做得到」的詞（有對應物品或設施）
2. 分三類：
   新字（seen=0）      每天最多引入 2 個
   弱字（miss>=ok 或 ok<2） 
   熟字（ok>=4 且 days>=3）
3. 抽取權重：
   到期的複習字（新字引入後的第 0 天、第 1 天、第 2 天）  權重 5
   弱字                                                  權重 3
   一般字                                                權重 1
   熟字                                                  權重 0.3（仍會出現，避免遺忘）
4. 不連續出現同一字；同一次最多 1 個新字
6. （M2 模擬後新增）還有字在複習期時不引入新字，讓新字的引入速度配合實際的出題量
7. （M3 起）**複習改用出題次數計算**：新字引入後還要再出 3 次，兩次之間至少隔 2 題別的；隔夠了就「到期」，有到期字時優先出它（不然字一多，到期字會被一大群弱字稀釋）
5. 干擾項 = 同模組、同詞類、已學過的字，優先挑易混淆的（例如 carrot 與 corn）
```

**複習時程**：新字第一次出現（天 0）→ 同日稍晚一次（約 5 分鐘後）→ 天 1 → 天 2。三天內共 4 次曝光，至少 3 次是需要選擇的情境。

**M2 模擬結果**（`tools/sim/sim_sched.js`，40 字、每 5 天解鎖 4 字、100 天）：

| 每天願望數 | 1 | 2 | 3 | 4 | 6 | 8 |
|---|---|---|---|---|---|---|
| 新字 3 天內 ≥3 次 | 0% | 18% | 43% | 50% | 95% | 98% |

- 弱字每次被選中的機率是熟字的 5～9 倍；單日新字不超過 2 個；沒有連續同字。
- **目標要每天約 6 個願望才達得到**。每天 1 個願望時，「不連續同字」和「3 天內 3 次」本身就互相矛盾。
- 遊戲的一天是 60 秒，「同日稍晚約 5 分鐘」在遊戲中不存在；「3 天」實際上是 3 分鐘。**待決定**：時間窗改用「接下來 N 次出題」計算，或增加每天的願望來源（M3 的多位居民、市集）。
- 目前遊戲只有 3 個候選字，每天 2 個以上願望即可達成目標。

**M3 決定與結果**：時間窗改用出題次數（第 7 條），同時加入多位居民增加每天的願望數。重跑 `sim_sched.js`：

| 每天願望數 | 1 | 2 | 3 | 4 | 6 | 8 |
|---|---|---|---|---|---|---|
| 新字引入後 12 題內再出 ≥3 次 | 100% | 100% | 100% | 100% | 100% | 100% |

弱字每次被選中的機率仍是熟字的 3～7 倍；單日新字不超過 2 個；沒有連續同字。代價是每天願望少時，新字引入得比較慢（每天 1 個願望時，100 天約引入 12 字）。

## 2. M1 原型審查（已用模擬驗證）

### 2.1 發現的問題

| # | 問題 | 嚴重度 | 處理 |
|---|---|---|---|
| 1 | 居民願望：背包有東西就自動交出，玩家沒有選擇，英文不影響成功 | 高 | **改為選取物品再交給居民**，選錯會搖頭，不扣東西（M2 已完成） |
| 2 | `ok` 在每天預報時就加，天氣字會在沒學會時淡出 | 高 | 套用 §1.1 定義；預報改為「選天氣圖示」互動（§4.3）（M2 已完成） |
| 3 | 玫瑰種在樹蔭永遠長不大（光 0.7 > 樹蔭最多 0.5），也沒有挖掉的方法 | 高 | 已改為連續速率生長（已套用）；新增鏟子（M2 已完成） |
| 4 | 數值太快：所有植物第一天就成熟，天氣幾乎沒有影響 | 高 | 已調整（見 2.2，已套用） |
| 5 | 雨天所有植物都停止生長 | 中 | 已解決（連續速率下雨天仍有 15% 光） |
| 6 | 重置存檔會被舊頁面的 `pagehide` 存檔蓋回去 | 中 | 已修：用 `?reset=1`，在新頁面載入時清除 |
| 7 | 教學固定叫玩家種紅蘿蔔，改種別的提示會錯 | 低 | 教學步驟改為檢查「是否已完成」而不是檢查種類（M2 已完成） |

### 2.2 模擬結果與採用的數值

用 `sim_m1.js`、`sim_m1b.js`、`sim_m1c.js` 以 Monte Carlo（每組 3,000 次）模擬。

**原模型的問題**：離散門檻（光照達標才長）搭配 20～30 秒的成熟時間，一天 60 秒，所以植物第一天就成熟，且玫瑰在樹蔭 100% 卡死。

**新模型**（已套用到 `game.js`）：生長速率 = `min(1, 光照 ÷ 光需求)`，水量低於 0.2 時停止；乾燥速率減半，澆水一次可撐約一天。

| 植物 | 成熟秒數 | 向陽勤澆 | 向陽只澆一次 | 樹蔭勤澆 | 樹蔭只澆一次 |
|---|---|---|---|---|---|
| 紅蘿蔔 | 75 | 2.0 天 | 2.6 天 | 2.5 天 | 4.2 天 |
| 豆子 | 110 | 2.9 天 | 4.9 天 | 3.7 天 | 6.2 天 |
| 玫瑰 | 150 | 4.1 天 | 7.5 天 | 6.5 天 | 12.1 天 |

（一天 60 秒。90% 分位數最慢：玫瑰樹蔭只澆一次 17 天，約 17 分鐘，屬於「偷懶的代價」可接受。卡死比例全部為 0%。）

**驗證結果**：天氣現在有意義（陰雨天延遲 1～3 天）、勤澆比不澆快約 1.5～2 倍、沒有任何組合卡死。

## 3. 核心系統

### 3.1 時間與天氣

| 項目 | 規則 |
|---|---|
| 一天 | 60 秒，之後換天氣 |
| 天氣 | 晴 0.4、多雲 0.25、雨 0.25、風 0.1，**不連續相同** |
| 預報 | 每天開始時播報；延伸層可看「明天預報」（氣象站，INd-Ⅱ-7） |
| 光照 | 晴 1.0、風 0.8、多雲 0.4、雨 0.15；樹蔭 ×0.5 |
| 水分 | 晴 -0.010/秒、多雲 -0.006、風 -0.015、雨 +0.08；澆水 +0.6 |
| 暫停 | 圖鑑、設定開啟時暫停時間 |
| 設定 | 上方齒輪按鈕：**中文字幕**開關（英文句子下方的中文翻譯：Pip 引導、居民願望、天氣播報、天氣題、日記選項；圖鑑的中文說明是科學內容，不受影響）、聲音開關；存在存檔，預設開 |

### 3.2 種植（含復原）

| 動作 | 規則 |
|---|---|
| 種 | 選種子再點空地；每塊地一株 |
| 澆水 | +0.6，上限 1 |
| 收成 | 成熟時點擊，得到作物 +1 星砂 |
| **鏟子（新增）** | 挖掉任何植物，**返還種子**，地塊恢復空地；解決種錯位置、種錯植物 |
| 枯黃 | 水量 < 0.08 時變黃，澆水立刻恢復，不會死 |

### 3.3 居民與願望（修正自動交付）

| 項目 | 規則 |
|---|---|
| 提出 | 氣泡顯示英文句（依階段加圖、中文）；點氣泡可重聽。**M2 實作**：重聽本身不算 `peek`（聽英文正是要鼓勵的事），在階段 1、2 點氣泡會露出隱藏的圖或中文，這時才算 `peek`；手上沒拿東西時點居民也是重聽 |
| **交付** | 玩家從背包**選一個物品**，再點居民。背包至少放 3 種物品（含干擾項，來自 §1.3 干擾規則）才算有效選擇 |
| 正確 | 星砂 +5、愛心動畫、該字 `ok +1`（若未用 peek） |
| 錯誤 | 居民搖頭，物品退回，該字 `miss +1`，句子再唸一次並露出圖。**不扣任何東西** |
| 下一個願望 | 由 §1.3 排程器挑選，約 2.5 秒後出現。**M2 實作**：背包裡的物品不顯示英文名稱，選物品時會唸出它的英文；`ok` 只在背包有 3 種以上物品時才算（開局只有 1、2 種時，答對不加 `ok` 也不加 `miss`） |
| 物品不足 | 玩家背包沒有可選項時，居民改提出「做得到的」願望（只能是已種過的作物） |

### 3.5 日記（名稱呼應的核心系統）

| 項目 | 規則 |
|---|---|
| 時機 | 每天結束時（60 秒的一天走完）自動進入「寫日記」，也是一次遊玩的自然結束點 |
| 內容 | 以簡單句型記錄當天發生的事，例如 `Today it was rainy. I planted a carrot.`，句子由當天的事件拼出，不是玩家自由輸入 |
| 決策 | 日記每句有一個空格，玩家從 3 個詞中**選一個填入**（天氣、作物、居民名稱），選項來自當天真正發生的事，答案是從當天的經歷中回想 |
| 失敗／復原 | 選錯會露出當天的小圖提示，可再選；日記一律會完成，不會漏寫 |
| ok | 第一次填對 |
| 價值 | 提供「以句子回顧」的機會（英語 Ae-Ⅲ-12、B-Ⅲ-1、Ad-Ⅲ-11），並讓核心層的單字在每天結尾再出現一次；日記本可以翻回前面的頁面，孩子能看到自己的島如何成長 |
| 忽略測試 | 3 選 1 亂猜 33%，但答案只能靠當天的記憶，不看英文也不看經歷就很難全對 |
| 核心層與延伸層 | 核心層：一句、一個空格；延伸層：三句、拼寫空格（4-Ⅲ-3） |
| M2 實作 | 句型：`Today it was ___.`、`I planted a ___.`、`I picked a ___.`、`I gave a ___ to the rabbit.`，事件句權重是天氣句的 2 倍。當天同類事件有兩種以上時，那些字不能當干擾項；湊不到 3 個選項的句型就不出（只有 3 種植物時，當天種了兩種就只會出天氣句）。答案字在階段 0 時選項附中文。寫完按 `Good night` 進入隔天；日記本（上方「日記」按鈕）可翻閱 |

### 3.6 家長端

長按設定 3 秒並解一題算術開啟。顯示：玩了多久、每個單字的 `ok / miss / days`、每個課綱條目是否接觸過、可重設進度。資料只存本機。

**實作**：點齒輪＝設定；**按住齒輪 3 秒**＝家長端。先答一題兩位數加法，用數字鍵輸入（不是選擇題，孩子亂猜進不來）。四個分頁：

- 課綱：24 組課綱條目，玩過對應機制的打勾（舊存檔從收成、居民、日記等資料推算）
- 重設：按兩次確認（5 秒內），用 `?reset=1` 在新頁面載入時清除

## 4. 各模組機制卡

### 欄位說明
**決策**＝玩家必須選擇什麼；**依賴**＝這個決策靠哪個概念或英文；**失敗／復原**；**ok**＝何時算答對；**忽略測試**＝亂點的結果。

### 4.1 植物（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | 哪種植物放哪一塊地（向陽或樹蔭）、何時澆水、要不要鏟掉重種 |
| 依賴 | 光與水的需求（INa-Ⅱ-7、INe-Ⅱ-11）；植物名稱英文（願望） |
| 失敗／復原 | 長得慢但不停；缺水停止、澆水恢復；鏟子重種 |
| ok | 願望交付時選對作物（§3.3） |
| 忽略測試 | 亂種亂澆：玫瑰種樹蔭要 6.5 天，種向陽要 4.1 天，缺水要 7.5 天，明顯較慢 |
| 課綱 | INb-Ⅱ-6、INa-Ⅱ-7、INe-Ⅱ-11、INd-Ⅱ-3 |

### 4.2 植物各部位（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | 居民要「根／花／種子」類的物品，玩家要選對植物來收成 |
| 依賴 | 「紅蘿蔔吃根、豆子吃種子、玫瑰看花」（INb-Ⅱ-6）；英文 root / flower / seed |
| 失敗／復原 | 收成錯植物不扣東西，可再種 |
| ok | `I want a root.` 之類的要求，選對作物 |
| 忽略測試 | 3 選 1，亂猜 33% |
| 課綱 | INb-Ⅱ-6、INb-Ⅱ-7 |
| 實作（2026-11-16） | 教學結束後，居民的願望候選除了作物名，也加入這些作物的部位字（root／seed／flower／fruit／stem），一起交給排程器出題：`I want a root.`、`I want some seeds.`…。紅蘿蔔＝根、豆子與玉米＝種子、玫瑰＝花、葡萄＝果實、馬鈴薯＝莖（塊莖）。氣泡的圖只畫部位本身，不畫作物；`ok`／`miss` 記在部位字上（選項數＝背包裡的作物種類） |

### 4.3 天氣（核心，草地）
| 欄位 | 內容 |
|---|---|
| 決策 | **每天早上居民問 `How is the weather?`，玩家從 4 個圖示中選出今天的天氣**；以及依天氣決定今天做什麼（雨天不澆水、晴天種玫瑰）。**M2 實作**：第 1 天不問（先讓教學進行）；卡片顯示方式依正確答案字的階段：0＝圖＋英文＋中文、1＝圖＋英文、2＝只有英文，可按放大鏡露出圖（算 `peek`）；回答前上方不顯示天氣圖示；重聽題目不算提示 |
| 依賴 | 天氣英文單字與圖示對應；雨天水分自動補充的因果（INd-Ⅱ-6、INd-Ⅱ-7） |
| 失敗／復原 | 選錯圖示會搖晃並再聽一次，不影響遊戲 |
| ok | 第一次就選對圖示 |
| 忽略測試 | 4 選 1，亂猜 25%；看天空其實也能答，所以這題訓練的是「英文單字和圖示的對應」，不是觀察 |
| 課綱 | INd-Ⅱ-6、INd-Ⅱ-7、INd-Ⅱ-4 |

### 4.4 衣物與天氣（核心，市集與居民）
| 欄位 | 內容 |
|---|---|
| 決策 | 居民說 `It is rainy. I need a ...`，玩家從衣物和用品中選（raincoat、umbrella、hat、coat） |
| 依賴 | 天氣字加衣物字的組合（INf-Ⅱ-4） |
| 失敗／復原 | 選錯居民淋濕變皺眉，換一個再選，不扣東西 |
| ok | 第一次選對 |
| 課綱 | INf-Ⅱ-4；英語 B-Ⅱ-1 |
| M3 實作 | 在市集出現（居民當客人）。句子改成 `It is rainy. What do I need?`，不用 `I need a ...`，因為冠詞 `an` 會洩漏答案是 umbrella。題目：sunny／hot → hat、rainy → umbrella 或 raincoat、cold → coat；架上 4 件（hat、coat、一件雨具、shoes），只有一件對。台灣晴天也常撐傘遮陽，所以晴天、熱的題目只放 raincoat、不放 umbrella。`ok`／`miss` 記在天氣或溫度字上。答對 ★+4；答錯卡片變淡、露出中文與天氣小圖 |

### 4.5 動物與棲地（核心，池塘森林）
| 欄位 | 內容 |
|---|---|
| 決策 | 居民動物說 `I like water.`、`I live in a tree.`，玩家要**建對應的棲地**（池塘、樹、草地） |
| 依賴 | 動物與環境的關係（INc-Ⅱ-8、INb-Ⅱ-7）；英文句型與地點字 |
| 失敗／復原 | 棲地不對動物就**不來**（不會離開）；棲地可拆除返還 50% 重建 |
| ok | 第一次就建對 |
| 忽略測試 | 3 種棲地亂建 33%，且資源有限所以亂建會浪費星砂（但可拆除返還） |
| 課綱 | INc-Ⅱ-8、INb-Ⅱ-5、INb-Ⅱ-7 |
| M3 實作 | 森林 7 塊空地（一開始開放 4 塊）；訪客說 `I am a duck. I can swim.` 這類句子（frog/fish 喜歡水、duck 會游泳、bird 住樹上、monkey 會爬樹、cow/horse 吃草）。點空地選 pond、tree、grass 蓋（每個 ★4），蓋好就交給訪客；`ok`／`miss` 記在句子裡的關鍵字（water、swim、tree、climb、grass）。蓋錯的棲地可以留給之後的動物，或用鏟子拆掉退 ★2。住下來 ★+3、進圖鑑、記進日記事件 |
| 擴建（M3 決定） | 原本只有 4 塊空地，住滿就不再有訪客。改為依 §3.4 用星砂擴建：第 5～7 塊依序 ★8、★10、★12，一次只顯示下一塊可以買的地；點一下顯示價格，3 秒內再點一次才買下（避免誤觸）。7 塊剛好容納 7 種動物，每場最多 7 次棲地決策 |

### 4.6 動物叫聲（核心，池塘森林）
| 欄位 | 內容 |
|---|---|
| 決策 | 聽叫聲，從 3～4 隻動物中選出是誰（同時有視覺：動物嘴巴動的畫面） |
| 依賴 | 不同動物有不同叫聲（INe-Ⅱ-5）；動物英文名 |

| ok | 第一次選對 |

### 4.7 水的三態與溶解（核心，海灘）
| 欄位 | 內容 |
|---|---|
| 決策 | 居民要「甜茶」：玩家選**熱水或冷水**來泡，並決定要不要攪拌。冷水糖會沉底，熱水很快溶解 |
| 依賴 | 溫度影響溶解（INe-Ⅱ-2）；`hot / cold / sweet / tea` 英文 |
| 失敗／復原 | 糖沒溶解居民說 `It is not sweet.`，可再加熱或攪拌，不扣材料 |
| ok | 第一次選熱水或做對 |
| 忽略測試 | 亂選有 50% 失敗，雖然不扣材料但耗時 |
| 課綱 | INe-Ⅱ-2、INe-Ⅱ-3、INc-Ⅱ-6 |
| M4 實作 | 海灘「甜茶」站：客人說 `I want sweet tea.`，選 hot 或 cold 的水壺（壺上有冒煙或冰塊的圖）。熱水約 1 秒糖就溶化；冷水糖沉在杯底，要攪 4 下。端出去時糖沒溶完，客人說 `It is not sweet.`，可再攪拌或改加熱水補救。第一次選的水算決策，只有 2 個選項，所以記在科學統計，不算單字 `ok`。完成 ★+3。冰塊與結冰（下段）尚未做 |

**冰塊與結冰**：冬天池塘結冰成為橋。玩家選擇把冰塊放在太陽下還是陰影裡，來決定能保存多久（INa-Ⅱ-4、INd-Ⅱ-1）。

| ok | 第一次放對 |

### 4.9 光與影（核心，洞穴）
| 欄位 | 內容 |
|---|---|
| 決策 | 聽 `Move the lamp to the left.` 這類指令移動燈或鏡子，把光導到暗處的植物；擋光物決定影子位置 |

| ok | 指令下一次移動就對 |
| 忽略測試 | 看光束就能調整，但**方位字不看英文會左右亂動**；可量測：左右指令第一次對的比例 |
| 課綱 | INe-Ⅱ-6、INa-Ⅱ-6、INc-Ⅱ-4 |

### 4.11 聲音（核心，燈塔）
| 欄位 | 內容 |
|---|---|
| 決策 A | **找走失的小動物**：霧中只聽得到叫聲，聲音大小代表遠近，左右代表方向，玩家決定往哪走。需視覺對應（波紋大小）供靜音使用 |
| 決策 B | **修樂器**：敲鐘、撥弦、敲鼓，其中一個因為被卡住而不振動，玩家要找出不振動的並放開 |
| 依賴 | 聲音來自振動、可經固體液體氣體傳播（INe-Ⅱ-5）；`loud / quiet / left / right / near / far` |
| 失敗／復原 | 走錯方向聲音變小，轉身即可；樂器可重新敲 |
| ok | 指令或提示出現後，第一次往正確方向或選對樂器 |
| 忽略測試 | 靜音玩家看波紋也能做；但**聲音大小與 `loud/quiet` 的對應**只能靠聽與讀，統計時分開記錄 |
| 課綱 | INe-Ⅱ-5 |
| M4 實作 A | 燈塔「霧中找朋友」站：霧裡看不到朋友，只看得到從左、前、右其中一邊傳來的波紋（越近越大、越多圈），也會播放叫聲。每走一步回饋 `It is louder!` 或 `It is quieter.`；走錯會變遠，不會卡住。走對 3 步就找到。每步第一次的選擇記科學統計（3 選 1） |
| M4 實作 B | 燈塔「修樂器」站：bell、drum、guitar、piano 其中一個卡住了，外觀看不出來。點樂器會發聲（`Ding!`、`Boom!`），正常的會抖動並出現波紋，壞的只顯示 `...`。找出來按 `Fix 修理`，選錯會提示「它沒壞，點點看會不會振動」。第一次修對記科學統計（4 選 1） |

### 4.12 磁鐵（核心，海灘）
| 欄位 | 內容 |
|---|---|
| 決策 | 沙灘上混著金屬和非金屬零件。玩家**先猜哪些會被吸**，放進「會吸」或「不會吸」箱子，再用磁鐵驗證；兩個磁鐵推船時選擇 N 或 S 面朝向 |
| 依賴 | 磁鐵只吸含鐵物體（INe-Ⅱ-7）；打破「金屬都會被吸」迷思（銅幣、鋁罐不吸）；`magnet / iron / metal / push / pull` |
| 失敗／復原 | 先猜錯沒有懲罰，驗證後會看到結果並可重新分類 |
| ok | 驗證前猜對 |
| 忽略測試 | 2 選 1 亂猜 50%，但驗證後不改的話零件用不了 |
| 課綱 | INe-Ⅱ-7 |
| M4 實作 | 海灘「磁鐵」站：每回合 5 樣東西，至少 2 樣含鐵（鐵釘、迴紋針、螺絲），至少 1 樣是**不會被吸的金屬**（銅幣、鋁罐），其餘是非金屬。先點東西再選 Yes／No，全部猜完才能按 `Check 驗證`；被吸的會跳起來，猜錯的標紅框可以改。猜錯的裡有銅幣或鋁罐時，顯示「不是所有金屬都會被吸」。只有驗證前的第一次猜測算進統計（2 選 1，記科學統計）。全對 ★+3。兩個磁鐵推船（N／S 面）尚未做 |

### 4.13 電路（核心，燈塔）
| 欄位 | 內容 |

### 4.20 食物鏈與生態平衡（延伸，生態研究所）
**重要設計變更**：用**承載量模型**，不做自由族群動態。

模擬結果（`sim_food.js`）：草、兔、狐的連續動態模型在 5 組參數下，300 天內**全部會崩潰**；就算加上保底，保底每 1～2 天就觸發一次（121～291 次/300 天），代表系統是靠作弊撐住的。

| 項目 | 規則 |
|---|---|
| 平衡值 | 草的承載量 = 草地面積 × 10；兔的平衡 = 草 ÷ 10；狐的平衡 = 兔 ÷ 4 |
| 變化 | 每天向平衡值靠近 1 格，**單調收斂，不會振盪或滅絕** |
| 玩家決策 | 增加草地、放置狐穴或兔窩，改變平衡值；介面用箭頭顯示每個物種「變多、變少、穩定」 |
| 事件 | 兔子變太多時草被吃光，玩家看到草地變禿，補種草或建狐穴 |
| 失敗／復原 | 任何比例都能收斂，不會滅絕 |
| ok | 事件前選出正確處置 |
| 課綱 | INa-Ⅲ-10、INc-Ⅲ-9、INe-Ⅲ-12 |
| M6 實作 | 研究島「生態研究所／食物鏈」：兩種情況（兔子太多、草被吃光；狐狸餓、兔子太少），從 4 個處置選一個（多種草、蓋狐狸窩、放更多兔子、把草割掉；第一種情況多種草或蓋狐狸窩都對）。選完用承載量模型模擬 5 天，數字旁顯示「↑ 變多／↓ 變少／－ 穩定」；每種動物至少保留 1 隻。選錯會看到變糟、說明原因，再回到原狀重選 |
| 長期經營 | 第一次打開食物鏈站後，玩家有一座自己的生態園（存檔 `eco`：草地 3 塊、草 30、兔 3、狐 1）。每天換日時往平衡靠近一格；連續平衡 3 天以上，每天有 35% 機會發生事件（外地兔子跑來 +6，或山上狐狸搬來 +3）。生態園有狀況時，食物鏈站出的就是自己的生態園，選對的處置會留下來（草地最多 6 塊），之後每天慢慢恢復；恢復期間和平衡時出練習題，並顯示平衡天數。模擬 200 輪 × 100 天（玩家都不處理）：約 43% 的天數有狀況、每 100 天約 15 次事件，兔子最少 3、狐狸最少 1，不會滅絕 |
